첨부된 과정은 **서비스 기획 → FastAPI 백엔드 → RDB/ORM → REST API·인증 → React 프론트엔드 → AI 활용 → LLM/RAG → 테스트·CI/CD → 프로젝트**까지 이어지는 풀스택 구조입니다.  또한 최종적으로 FastAPI·React·PostgreSQL·LangChain 기반 서비스를 구축하고 CI/CD까지 적용하는 프로젝트가 포함되어 있으므로 , 강사 입장에서는 단순히 “프로그래밍을 해봤는가?”보다 **어디까지 경험했고, 어느 부분을 스스로 수행할 수 있으며, 과정 후 어떤 직무로 취업하고 싶은가**를 파악하는 설문이 더 유용합니다.

아래처럼 **20문항**으로 구성하는 것을 권장합니다. 객관식, 5점 척도, 복수선택, 주관식을 혼합했습니다.

## 특히 강사가 주목할 문항

20문항 전체를 동일하게 볼 필요는 없습니다. 실제 수업 운영에는 **5, 6, 10, 11, 14, 15, 17, 19번**의 가치가 특히 높습니다.

**5번 코드 독해 능력**은 AI가 코드를 생성하는 환경에서 매우 중요하고, **6번 디버깅 능력**은 실습 수업의 진행 속도와 직접적으로 연결됩니다. **10·11번 Backend/DB 능력**은 FastAPI와 PostgreSQL 학습 난이도를 예측할 수 있고, **14번 Git/GitHub**는 팀 프로젝트 운영에 직접 영향을 줍니다.

또한 **17번 프로젝트 경험**은 객관식 응답보다 실제 개발 수준을 판단하기 좋은 자료이며, **19번 희망 직무**는 과정 후반 프로젝트에서 역할을 배정하거나 포트폴리오 방향을 설정하는 자료로 활용할 수 있습니다. 최종 프로젝트도 기업 요구사항을 기반으로 기획부터 배포, LLM·RAG 연동, 문서화까지 수행하도록 구성되어 있으므로  초기 설문 결과를 **팀 구성과 역할 배분까지 연결하는 것**이 효과적입니다.

그리고 OT에서는 앞서 만든 **① 인터넷 기초평가 20문항 + ② 프로그래밍 기초평가 20문항**을 실제 객관적 역량 점수로 사용하고, 이번 **20문항 설문은 자기평가·경험·진로 자료**로 분리해서 관리하는 것이 가장 좋습니다. 즉, **시험점수와 자기평가를 비교**하면 “본인이 생각하는 수준”과 “실제 기초 역량”의 차이까지 파악할 수 있습니다.
