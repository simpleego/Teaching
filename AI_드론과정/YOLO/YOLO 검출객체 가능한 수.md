## 결론 한 줄

> **최신 YOLO는 “검출 가능한 객체 수에 이론적 한계가 없다”.**
> 다만 **학습에 사용한 데이터셋의 클래스 수만큼만 검출**합니다.

---

## 왜 “무제한”이라고 말할 수 있나?

YOLO는 **모델 구조상 클래스 수가 고정되어 있지 않습니다.**

* 출력 구조:

  ```
  [박스 좌표] + [objectness] + [클래스 확률 N개]
  ```
* 여기서 **N = 사용자가 정의한 클래스 수**

👉 즉,

* 1개 클래스 → 1개만 검출
* 80개 클래스 → 80개 검출
* 500개 클래스 → 500개 검출
* 1,000개 이상도 가능 (이론적으로)

---

## 사람들이 흔히 말하는 “YOLO는 80개까지”의 정체

이건 **YOLO의 한계가 아니라, 기본 학습 데이터셋(COCO)의 한계**입니다.

### COCO 데이터셋

* 클래스 수: **80개**
* 그래서:

  * YOLO 기본 pretrained 모델 → **80종 객체만 검출**

📌 이 때문에 오해가 생김

> ❌ “YOLO는 80개까지 가능”
> ✅ “COCO로 학습된 YOLO는 80개를 배운 상태”

---

## 최신 YOLO 기준 클래스 수 예시

| 사용 시나리오            | 검출 가능 객체 수             |
| ------------------ | ---------------------- |
| 기본 COCO pretrained | 80개                    |
| 커스텀 데이터셋(소규모)      | 5 ~ 50개                |
| 산업용 관제 시스템         | 50 ~ 300개              |
| 대규모 비전 시스템         | 수백 ~ 수천 개 (현실적 한계는 있음) |

---

## 현실적인 “실무 한계”는 어디서 오나?

이론 ≠ 실무입니다.
실제로는 아래가 한계를 만듭니다.

### 1️⃣ 데이터 문제

* 클래스 1개당 **충분한 샘플 필요**
* 500개 클래스인데 각 10장 → ❌ 학습 붕괴

### 2️⃣ 연산량 증가

* 클래스 수 ↑
  → 출력 채널 ↑
  → 연산량 ↑
  → FPS ↓

### 3️⃣ 클래스 간 혼동

* 비슷한 객체 많을수록

  * 오검출
  * confidence 불안정

## 중요한 포인트 (많이 헷갈리는 부분)

### ❓ “한 화면에서 동시에 몇 개 객체까지 검출 가능?”

→ **이것도 제한 없음**

* YOLO는 한 프레임에서

  * 사람 50명
  * 차량 100대
  * 객체 수백 개
    **동시 검출 가능**

제한은:

* GPU 성능
* NMS 처리량
* FPS 요구사항
