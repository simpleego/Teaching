아래는 앞서 추가한 **6~10번 단답형 문제**에 대한 **출제의도와 문제해설**입니다. 첨부 자료의 `사용자 여정 맵 → 기능 우선순위 → 와이어프레임/프로토타입 → 사용성 테스트` 학습 흐름에 맞춰 작성했습니다. 

| 번호     | 정답                 | 출제의도                                                         | 문제해설                                                                                                                                                                                                             |
| ------ | ------------------ | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **6**  | 사용자 여정 맵(CJM)      | 사용자가 서비스를 이용하는 전체 흐름을 분석하고 시각화하는 개념을 이해하고 있는지 확인한다.          | **사용자 여정 맵(Customer Journey Map, CJM)**은 사용자가 서비스를 이용하면서 거치는 단계, 행동, 접점(Touch Point), 경험 등을 순서대로 정리한 것이다. 서비스 기획자는 이를 통해 사용자가 어디에서 불편을 느끼는지 파악하고 개선할 수 있다. 첨부 자료에서도 사용자 서비스 이용 흐름의 시각화와 터치포인트 분석을 핵심 내용으로 제시한다.  |
| **7**  | MoSCoW             | 여러 서비스 기능 중 무엇을 먼저 개발해야 하는지 판단하는 대표적인 우선순위 기법을 알고 있는지 평가한다.  | **MoSCoW 기법**은 요구사항이나 기능을 `Must have`, `Should have`, `Could have`, `Won't have`로 구분하여 우선순위를 결정하는 방법이다. 제한된 개발 기간과 자원 안에서 반드시 필요한 핵심 기능을 먼저 선정할 때 활용할 수 있다. 첨부 자료에서도 기능 명세와 우선순위 설정 방법으로 MoSCoW 기법을 명시하고 있다.     |
| **8**  | 와이어프레임(Wireframe)  | 실제 UI 개발 전에 화면의 기본 구조와 구성 요소를 설계하는 개념을 이해하는지 확인한다.           | **와이어프레임**은 웹이나 앱 화면을 실제로 개발하기 전에 메뉴, 버튼, 이미지, 텍스트 등의 위치와 화면 구조를 단순하게 표현한 설계도이다. 디자인의 세부적인 색상이나 효과보다 **화면 구성과 정보 배치**를 확인하는 데 목적이 있다. 첨부 자료에서는 와이어프레임과 화면 흐름 설계를 주요 학습 내용으로 제시한다.                                |
| **9**  | 프로토타입(Prototype)   | 와이어프레임과 프로토타입의 차이를 이해하고 실제 사용자 경험을 사전에 검증하는 방법을 알고 있는지 평가한다. | **프로토타입**은 완성된 서비스 이전에 실제 서비스와 유사한 화면 이동, 버튼 클릭 등의 동작을 시험할 수 있도록 만든 시제품이다. 와이어프레임이 화면의 **구조**를 보여주는 데 초점이 있다면, 프로토타입은 화면 간 이동과 상호작용을 확인할 수 있다는 점이 특징이다. 첨부 자료에서도 인터랙티브 프로토타이핑과 화면 흐름 설계를 다룬다.                    |
| **10** | UT(Usability Test) | 프로토타입 제작 이후 실제 사용자를 통해 서비스의 문제점을 확인하고 개선하는 절차를 이해하는지 평가한다.   | **UT(Usability Test, 사용성 테스트)**는 사용자가 프로토타입이나 서비스를 직접 사용하도록 한 뒤 사용 과정의 어려움, 불편함, 오류 등을 관찰하여 개선점을 찾는 방법이다. 테스트 결과와 사용자 피드백을 다음 설계에 반영한다. 첨부 자료에서도 UT 설계, 테스트 진행, 피드백 반영을 학습 내용으로 제시한다.                            |

수업용 평가표에 넣는다면 **출제의도는 한 문장**, **문제해설은 2~3문장 정도**로 축약하는 방식이 가장 활용하기 좋습니다. 예를 들어 7번은 `기능 우선순위를 결정하는 대표적인 기법을 이해하는지 평가한다.` 정도로 줄여 사용할 수 있습니다.
