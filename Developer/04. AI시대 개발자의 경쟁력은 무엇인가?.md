이 질문이 사실 핵심입니다.

많은 사람들이 AI 시대를 이야기할 때 아직도 관점이 이렇습니다.

"개발자가 AI보다 코딩을 잘해야 살아남는다."

그런데 실제로는 이미 많은 영역에서 AI가 평균 개발자보다 코드를 더 빨리 만듭니다.

그래서 질문이 바뀌어야 합니다.

"왜 현업 전문가가 AI를 쓰면 개발자를 완전히 대체하지 못하는가?"

결론부터 말하면

현업자는 보통

무엇을 만들어야 하는지(What) 는 잘 압니다.

반면 개발자는

그것을 어떻게 안정적으로 만들지(How) 를 압니다.

AI는 둘 다 어느 정도 알지만 최종 책임은 지지 않습니다.

예를 들어 은행 직원이 있다고 해보자

은행 대출 담당자가 AI에게 말합니다.

"우리 대출심사 시스템 만들어줘"

AI는 꽤 괜찮은 결과를 냅니다.

DB 설계
화면 설계
API 설계
인증 구현

심지어 CRUD 수준이면 거의 완성품이 나올 수 있습니다.

여기까지만 보면 개발자가 필요 없어 보입니다.

하지만 실제 서비스는 여기서부터 시작

대출 신청자가 100명이 아니라 100만 명이면?

갑자기 문제가 생깁니다.

예를 들어

동시접속자 증가
DB Lock 발생
트랜잭션 충돌
API Timeout
캐시 불일치
장애 복구


이런 것은 대출 업무를 잘 안다고 해결되지 않습니다.

현업자가 가장 자주 부딪히는 문제

예를 들면 쇼핑몰입니다.

업무 담당자는 이렇게 생각합니다.

상품
주문
결제
배송


끝.

그러나 개발자는 바로 질문합니다.

결제 성공 후 주문 저장 실패하면?

주문 저장 후 배송 생성 실패하면?

결제를 두 번 누르면?

재고가 1개 남았는데 동시에 100명이 주문하면?

환불 중 서버가 죽으면?


현업자는 보통 이런 생각을 하지 않습니다.

왜냐하면 이것은 업무 문제가 아니라 시스템 문제이기 때문입니다.

AI도 여기서 약해진다

AI는 대부분의 패턴을 알고 있습니다.

예를 들면

결제 시스템 설계해줘

하면

Saga Pattern
Event Driven Architecture
Message Queue
Outbox Pattern
Redis Cache


같은 것도 제안합니다.

그런데 AI는 모릅니다.

현재 회사 상황이

서버 3대
개발자 2명
예산 없음
트래픽 하루 5천명


인지,

서버 100대
MSA 환경
Kubernetes
트래픽 하루 1억건


인지.

둘 다 정답을 제시하기 때문입니다.

그래서 판단이 필요합니다.

현업자가 AI를 사용할 때 발생하는 실제 문제

제가 보기에는 3가지입니다.

1. AI 결과가 맞는지 검증 불가

AI가 말합니다.

SELECT *
FROM orders
WHERE status='COMPLETE'


현업자는

"좋아 보이는데?"

라고 생각합니다.

개발자는

"인덱스 없으면 죽겠는데?"

를 봅니다.

2. 장애를 예측하기 어려움

AI가 만든 시스템은

평상시 100점


일 때가 많습니다.

문제는

트래픽 폭증
DB 장애
네트워크 단절
메모리 부족


상황입니다.

이건 수많은 장애 경험이 있어야 합니다.

3. 요구사항 변화를 구조에 반영하기 어려움

실제 프로젝트는

1월
주문 시스템 개발


하다가

2월
정기구독 추가

3월
해외결제 추가

4월
멤버십 추가


됩니다.

초기 설계가 잘못되면 나중에 전부 다시 뜯어고쳐야 합니다.

이걸 "확장 가능한 구조"라고 합니다.

그래서 앞으로 개발자가 사라지는가?

저는 "일부는 사라지고 일부는 더 중요해질 것"이라고 봅니다.

특히 없어질 가능성이 높은 역할은

요구사항 받아서
CRUD 만들고
게시판 만들고
화면 연결하는 역할


입니다.

AI가 매우 잘합니다.

반대로 더 중요해질 역할은

시스템 설계
아키텍처
성능 최적화
보안
운영
장애 대응
기술 의사결정


입니다.

이건 아직도 경험의 비중이 큽니다.

비유하면,

AI는 이미 "엄청나게 똑똑한 신입사원" 에 가깝습니다.

하지만 회사에서 가장 중요한 사람은 신입사원이 아니라

"저 기능 추가하면 6개월 뒤 큰 사고 난다."

"그 설계는 우리 트래픽에서는 안 된다."

"이 장애는 예전에 겪어봤다."

라고 말할 수 있는 사람입니다.

그래서 앞으로 가장 강력한 조합은

현업 전문가 + AI도 아니고, 개발자 + AI도 아닙니다.

현업 지식이 있는 개발자 + AI

입니다.

왜냐하면 이 사람은 "무엇을 만들어야 하는지"와 "어떻게 만들어야 하는지"를 둘 다 이해하기 때문입니다. AI가 강해질수록 오히려 두 영역을 연결할 수 있는 사람이 가장 희소해질 가능성이 높습니다.
